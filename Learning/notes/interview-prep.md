## 1. Rim Light 边缘光

**骨架：**
- 原理：N dot V 中心 1 边缘 0，用 1-NdotV 让边缘变亮
- 造型：pow(rim, 指数) 控粗细，指数大=细，小=宽
- 压暗：背光面 dot(N,L) < 0 时压暗，否则像物体自己发光
- 叠加：加法加到最终色（final + rim），不是 lerp 覆盖

**必答点：**
- saturate 防背面 NdotV 为负导致 rim > 1
- exp2(lerp(3,0,x)) 防指数趋 0 时 pow 全白失控
- 参数：颜色、强度(alpha)、粗细(指数)、内部距离、硬边开关、暗部遮罩、遮罩贴图

**易错：**
- 说混合会让人以为 lerp，实际是加法
- 压暗理由：背光面无光还亮边 = 物体自发光，破坏光照统一感

## 2. Outline 描边

**骨架：**
- 法线外扩 + Cull Front 只渲染背面
- 背面外扩后，轮廓外露一圈 = 描边
- 和 Rim 区别：Rim 靠 N dot V（视角、表面光）；Outline 靠几何外扩（线、与光无关）

**必答点：**
- 机制：外扩背面在轮廓外没遮挡露出来；轮廓内被正面盖掉（深度测试，不是渲染顺序）
- 硬边断裂：每个面法线不同，顶点朝不同方向推，裂开
- 修复：平滑法线（烘焙到顶点色/UV），用 OutlineSmoothNormalsGenerator
- 和 Rim 不能同 Pass：Cull 模式冲突（Cull Front vs Cull Back）

**易错：**
- 别把 Rim（表面光）和 Outline（线）混为一谈
- 先画正面再画背面不是关键，深度测试才是

## 3. MatCap

**骨架：**
- 把光照烤进一张球面贴图，渲染时查表，不算真实光照
- 贴图 = 法线方向到外观 的查找表
- 采样：法线转观察空间，取 XY，乘 0.5 加 0.5，当 UV

**为什么观察空间：** 贴图从相机视角拍的，法线转到相机空间才能和贴图位置对应

**必答点：**
- 高光暗部都画在贴图里，不用真实光照也有质感
- 项目额外：颜色混合、光照开关、阴影遮罩、旋转、三种混合模式（加/乘/lerp）

**易错：** 别以为 MatCap 需要真实光照计算

## 4. 法线贴图与切线空间

**骨架：**
- 低模表面表达高模细节
- 切线空间：法线相对模型表面自己定义
- 用 TBN（切线T、副切线B、法线N）从切线空间转到世界空间

**为什么切线空间：**
- 世界空间法线绑死在固定方向，模型旋转/形变/骨骼动画就错
- 切线空间可复用、可动画、可换模型

**必答点：**
- 解码：normal = tex * 2 - 1
- Z 通道：z = sqrt(1 - x*x - y*y) 取正根
- TBN 正交化：Gram-Schmidt
- 两张法线打包：RG 一张、BA 一张（不是 RG 加 GA）
- 也可反过来把光方向转到切线空间做光照

**易错：**
- 通道说法：RG 加 BA，不是 RG 加 GA
- 法线变换用模型矩阵的逆转置（非均匀缩放时）；均匀缩放可直接用 M 再归一化

## 5. PBR 三要素

**骨架：**
- F0：垂直入射反射率。非金属约 0.04（水 0.02、塑料 0.04）；金属高且带颜色（金偏黄、铜偏红）
- 金属度：0=非金属（有漫反射加弱镜面），1=金属（无漫反射，Albedo 当 F0）
- 粗糙度：微表面法线分布，影响 D 项。0=光滑锐利，1=粗糙发散
- 能量守恒：出射小于等于入射，漫反射和镜面此消彼长

**MR 工作流：**
- Albedo 独立一张：非金属存漫反射色，金属存 F0
- MR 贴图打包：粗糙度 加 金属度（不是 Albedo）

**易错：**
- 金属 F0 不是接近 1，是带颜色的反射率
- 粗糙度是 D 项的输入，不是用 D 表示
- MR 只打包金属度加粗糙度，Albedo 单独

## 6. 坐标空间变换

**骨架：**
- OS（对象）到 WS（世界）到 VS（观察）到 CS（裁剪）到 NDC 到 屏幕
- 矩阵：M（模型）到 V（视图）到 P（投影），合称 MVP

**法线特殊：**
- 位置用 M，法线不能直接用 M
- 非均匀缩放会破坏法线的垂直性
- 法线用 M 的逆转置
- 均匀缩放/纯旋转时，可直接用 M 再归一化

**必答点：**
- TransformObjectToWorldNormal 内部就是逆转置
- 法线贴图还要 TBN 从 TS 到 WS，和 OS 到 WS 是两个不同变换

## 7. DrawCall 与合批

**骨架：**
- DrawCall = CPU 向 GPU 提交一次绘制
- CPU-bound 才卡（提交速度跟不上 GPU）

**减 DrawCall：**

| 技术 | 优化什么 | 代价 |
|---|---|---|
| 静态合批 | 合并静态网格 | 占内存、视锥剔除失效 |
| 动态合批 | 小网格运行时合并 | 顶点数限制、开销不小 |
| SRP Batcher | 不合并网格，只减少材质属性切换 | 换 Shader/变体就打断 |
| GPU Instancing | 同网格加同材质，一次画多实例 | 需相同网格材质 |

**必答点：**
- SRP Batcher 不减少 DrawCall，只减少状态切换
- 打断原因：CBUFFER 常驻显存，换 Shader/变体就换块 CBUFFER
- 静态合批和动态合批互斥
- Instancing 和 SRP Batcher 可共存，优化不同层面

## 8. 纹理压缩

**为什么压缩：** 显存 加 带宽（移动端最大瓶颈）

**BC 系列：**

| 格式 | 内容 | 用途 |
|---|---|---|
| BC1 | RGB（标准无 alpha） | 颜色贴图，最省 |
| BC3 | RGB 加完整 8-bit Alpha | 带 alpha 的颜色 |
| BC4 | 单通道 | 粗糙度/AO/高度 |
| BC5 | 双通道 | 法线 XY |
| BC7 | 高质量 RGBA | 质量最好，体积大 |

**移动端：** ASTC 优先（块大小可调），ETC2 老旧淘汰

**为什么法线用 BC5：**
- 法线是数据不是颜色，精度不够光照会错
- 存 XY，Z 用 sqrt(1-x*x-y*y) 解
- 颜色能低精度：人眼对颜色误差不敏感，对光照异常敏感

**易错：** BC1 标准无 alpha，要 alpha 用 BC3/BC7

## 9. Shadow 原理

**骨架：**
1. 从光源视角渲染场景，只存深度，得到 Shadow Map
2. 渲染时把像素转光源空间，算到光源深度
3. 比深度：像素深度 大于 贴图深度，被挡，在阴影里
4. 结果乘到光照上

**瑕疵：**

| 问题 | 原因 | 解法 |
|---|---|---|
| 锯齿 | Shadow Map 分辨率不够 | PCF、CSM、提分辨率 |
| Shadow Acne | 浮点精度导致自比较误判 | Bias（深度偏移/法线偏移） |
| Peter Panning | Bias 太大，阴影和物体脱开 | Bias 适中，优先法线偏移 |

**必答点：**
- PCF：对周围多个纹素各比一次取平均，得到软边
- CSM：近处高精度、远处低精度
- 背面渲染时纯深度偏移会加重痤疮，要配法线偏移

## 10. 各向异性

**骨架：**
- 表面有方向性微观结构（拉丝纹、头发丝、V 型凹槽）
- 高光垂直于纹理/切线方向拉伸，不是沿纹理！

**为什么：**
- 沿 T 方向：表面连续，法线变化慢，高光锐利
- 垂直 T 方向：法线变化快，高光分散
- 两个方向不一致，形成一条线

**Kajiya-Kay（头发）：**
- 用切线 T 代替 N
- 高光基于 T 和视线、光线夹角
- 两层偏移 T 模拟多层反射

**易错：** 高光垂直于纹理方向拉伸，不是沿纹理

## 11. 后处理

**骨架：**
- 场景渲染完后，对整张画面在屏幕空间做的二次处理
- URP 在 AfterRendering 阶段，通过 Renderer Feature 插入

**常见效果：** Bloom、ToneMapping、Color Grading、Vignette、DOF、Motion Blur、抗锯齿

**顺序原则（按技术依赖，不按使用频率）：**
- Bloom 必须在 ToneMapping 之前：ToneMapping 把 HDR 压到 0~1，超过 1 的亮部被压没，之后再 Bloom 提不出真高光
- Color Grading 在 ToneMapping 之后（LDR 调色）
- DOF/运动模糊依赖深度/运动向量，靠前

**性能优化：** 降分辨率、合并 Pass、减 Pass 数量、避免不必要读写

**易错：**
- Color Grading 的 LUT（3D 调色表）不等于 预积分皮肤的 LUT（2D，材质阶段，SSS 近似）
- 后处理性能优化 不等于 DrawCall 合批（后者是 CPU 提交开销）

## 12. URP 管线结构

**三层：**

- RenderPipelineAsset（管线资产，指定 Renderer、质量档）
  - UniversalRenderer / RendererData（这个档位有哪些 Pass、挂哪些 Feature）
    - ScriptableRendererFeature（在哪插）
      - ScriptableRenderPass（插什么）

**Feature vs Pass：**
- Feature 决定在哪插（RenderPassEvent 时机）
- Pass 决定插什么（具体渲染逻辑）

**Pass 两个方法：**
- Configure/OnCameraSetup：申请 RenderTarget、定执行时机
- Execute：CommandBuffer 录制绘制/Blit 命令

**插入时机：** BeforeRenderingOpaques / AfterRenderingTransparents / BeforeRenderingPostProcessing 等，插错效果就不对

## 13. 前向 vs 延迟渲染

| | 前向 | 延迟 |
|---|---|---|
| 光照 | 每个物体直接算完 | 先写 G-Buffer，再全屏统一算光照 |
| 多光源 | 物体乘光源，光源多就慢 | 光照只算一次，光源多不怕 |
| MSAA | 支持好 | 代价高（G-Buffer 每采样点都存） |
| 透明 | 好处理 | 要另外前向处理 |
| 带宽 | 低 | 高（G-Buffer 读写） |

**移动端前向：** 带宽是最大瓶颈，G-Buffer 读写太贵；光源少，前向劣势不明显；用烘焙

**3A 延迟：** 光源多（几十上百），带宽充足

**进阶：**
- G-Buffer 位置常用深度反推（省带宽），法线存两通道解第三通道
- 前向有 Forward+（Tile-based）缓解多光源：屏幕切 tile，每 tile 只算影响它的光源

## 14. 半透明渲染与排序

**骨架：**
- 半透明要和背后混合，必须等 opaque 画完
- opaque 可 ZWrite On 无序画（深度测试剔除）
- 半透明关 ZWrite、保留 ZTest，从远到近画

**为什么关 ZWrite 留 ZTest：**
- ZTest：被不透明物体挡住的透明像素直接丢弃，省性能
- 关 ZWrite：否则挡住后面更远的透明物体，导致远处的画不出来

**排序问题：**
- 混合顺序相关（A 前 B 后 不等于 B 前 A 后）
- 物体级排序解决不了：同一物体自相交、两透明物体深度交错
- 逐像素排序太贵几乎不用
- 无解时：接受 / Alpha Test 替代 / OIT（顺序无关的透明，代价高）

**Alpha Test vs Alpha Blend：**

| | Alpha Test | Alpha Blend |
|---|---|---|
| 结果 | 二值（全画/全不画） | 部分透明混合 |
| 写深度 | 写 | 不写 |
| 排序 | 不需要 | 需要 |

**易错：** OIT 是顺序无关，不是无光

## 15. Early-Z / Overdraw

**Early-Z：**
- 片元 shader 之前先做深度测试，失败的像素跳过 shader
- 减少被遮挡像素的片元着色开销（不是减少 Overdraw 次数本身）

**回退 Late-Z 的原因：**
- clip / discard / 写 gl_FragDepth 让像素是否存活、最终深度变成运行时才知道
- GPU 不敢提前丢，只能等 shader 跑完再测
- 所以 Alpha Test（clip）会破坏 Early-Z

**Overdraw：**
- 同一像素被画多次
- 半透明重灾区（不写深度，每多一个 DrawCall 就再画一遍）

**优化：**
- 不透明从近到远画（Early-Z 剔除后面）
- 减半透明层数、合并粒子、避免全屏半透明
- 深度预 Pass（Depth Prepass）

## 16. 抗锯齿

**锯齿成因：**
- 光栅化：像素只有覆盖/不覆盖，硬切阶梯（几何锯齿）
- 高频信息：描边、色块交界、高光（着色锯齿）

**三类方案：**

| 方案 | 机制 | 解决 | 代价 |
|---|---|---|---|
| SSAA | 高分辨率渲染再缩小 | 全部 | 最贵 |
| MSAA | 像素内多子采样点，光栅化阶段覆盖测试多次，着色一次 | 几何边缘 | 延迟下 G-Buffer 乘采样数爆炸 |
| FXAA | 屏幕空间找边缘再模糊 | 屏幕边缘 | 糊细节 |
| TAA | 运动向量累积多帧 | 全部 | 拖影 ghosting |

**MSAA 精确说法：** 光栅化阶段每子采样点覆盖测试，片元 1 次着色 N 次采样，resolve 按覆盖比例混合。不是加权平均周围像素（那是 FXAA）。

**延迟 MSAA 贵：** G-Buffer 每个采样点都存，显存/带宽乘 N

## 17. LOD

**骨架：**
- Level of Detail，按距离切换不同精度版本
- 近处高模，远处低模

**形式（不只网格）：**
- 网格 LOD、材质 LOD、Shader LOD、动画 LOD、纹理 LOD（Mipmap）、阴影级联（CSM）
- 核心思想：按距离降精度

**为什么用：** 减少顶点/三角形数，省顶点处理加光栅化。量级：高模 5 万面 vs 低模 5 千面，差 10 倍

**切换问题：**
- 跳变（popping）用交叉淡入淡出（crossfade/dither）
- 临界距离反复切用迟滞（hysteresis）
- 两者解决不同问题：迟滞防抖动，淡入淡出防视觉突变

**NPR 的 LOD 更保守：** 描边在低模上易断，色阶硬边让多边形棱角更明显

## 18. 遮挡剔除

**两种剔除：**
- 视锥剔除：物体在视野外，不画（CPU，包围盒 vs 视锥）
- 遮挡剔除：物体在视野内但被挡住，不画

**实现两条路：**
- CPU 软件光栅化（维护低精度深度缓冲）
- GPU 遮挡查询（Occlusion Query，画完遮挡物查询，结果下一帧才回来）

**方案：**
- 离线烘焙：预计算哪些区域能看到哪些物体
- 运行时：先画大遮挡物，再查询小物体

**核心难点：误剔除**
- 判断被挡但实际没挡，物体闪烁
- 必须保守：宁可多画，不可错剔
- 用保守包围盒 加 接受一帧延迟

## 19. 色彩空间（sRGB / Linear）

**骨架：**
- Linear：物理线性，光照计算必须在此空间
- sRGB：带 gamma 编码（约 2.2），为匹配人眼感知、省存储

**为什么 sRGB 存储：**
- 8-bit 存线性值，暗部码值太少，出现 banding（色阶断层）
- sRGB 把码值往暗部倾斜，视觉均匀，8-bit 够用

**哪些勾 sRGB：**
- 颜色贴图（Albedo / 自发光）勾
- 数据贴图（法线 / 粗糙度 / 金属度 / AO / 遮罩）不勾，勾了被非线性解码掰弯

**工作流：**
1. 颜色贴图 GPU 自动 sRGB 到 Linear
2. 光照全程 Linear
3. 输出编码回 sRGB

**易错：** 法线勾 sRGB，0.5 被解码成约 0.21，乘 2 减 1 后法线方向偏，光照错

## 20. Ramp / 三色阶

**为什么分层：** 卡通量化光照，N dot L 切成几段（亮部 / 暗部1 / 暗部2）

**项目实现（LitMain.hlsl 150-187）：**
1. halfLambert = dot(N,L) 乘 0.5 加 0.5
2. 阈值加羽化算两个过渡因子（shade1、shade2）
3. lerp(亮部, lerp(暗部1, 暗部2, shade2), shade1)

**Ramp 贴图 vs 硬编码：**

| | 硬编码 | Ramp 贴图 |
|---|---|---|
| 本质 | 参数写在 shader | 查找表（横 N dot L，纵颜色） |
| 风格 | 改参数 | 美术画贴图，能做复杂色带 |
| 开销 | 无额外采样 | 多一次采样 加 额外制作 |
| 羽化 | 浮点参数，更精细 | 离散采样，分辨率不够会断层 |

**项目选硬编码：** 颜色简单，羽化控制更灵活

## 21. 卡通高光

**和 PBR 区别：** PBR 是 GGX 连续衰减；卡通高光形状化，阈值化成硬边块或用贴图控形状

**项目实现（LitMain.hlsl 189-222）：**
1. H = normalize(V 加 L)
2. highLightFactor = saturate(dot(H,N) 乘 0.5 加 0.5)（映射到 0~1，阈值可落任意位置）
3. 两种模式：色阶（step 硬边）/ 柔边（pow 软过渡），_ToggleHighLightSoft 切换
4. 乘高光遮罩贴图 加 高光贴图控形状
5. 阴影遮罩：暗部高光压暗

**为什么形状可控：** 物理高光是圆/椭圆，卡通需要发型高光、眼睛高光点，贴图更灵活

**加分：** 用 N dot H（Blinn-Phong 思路）不是 R dot V，更省且掠射角更稳

## 22. 自发光 Emissive

**骨架：**
- 材质自己发光，加到最终色，不参与光照计算
- 光照为 0 时也亮

**关键（面试必问）：**
- 不照亮别人：不是光源，旁边物体不会因此变亮
- 不投射阴影：没有光被挡的概念
- 不受阴影影响：计算里没有 dot(N,L) 和 shadow

**项目实现（314-374）：**
- 固定：贴图.rgb 乘颜色 乘 贴图.a（alpha 当强度）
- 动画：UV 滚动/旋转/pingpong、cos 颜色变化、视角变化（1-NdotV）
- 最小 alpha：step(0.005, emissiveIntensity) 防微弱发光噪点

**易错：** 说受光面才发光 应改为 普通材质依赖光照，自发光不依赖

## 23. 阴影接收细节

**项目代码（LitMain.hlsl 111-169）：**

- GetMainLight(TransformWorldToShadowCoord(IN.positionWS)) 转阴影空间
- shadowAttenuation = saturate(lightMain.shadowAttenuation - _FloatShadowIntensity) 减
- halfLambert = lerp(halfLambert, halfLambert 乘 shadowAttenuation, _ToggleShadowReceive) 乘到 N dot L

**必答点：**
- 先 TransformWorldToShadowCoord 把世界位置转阴影空间才能查 Shadow Map
- _FloatShadowIntensity 是减在 shadowAttenuation 上，不是乘 N dot L
- 副作用：减 0.3 时亮面也压暗，不只加深阴影
- 为什么乘 N dot L：阴影本质是光被挡、受光量变少，乘受光量物理正确；从最终色减会破坏暗部色和高光
- 精确：受光量 = N dot L（朝向） 乘 shadowAttenuation（是否被挡），两者独立

## 24. 变体管理

**骨架：**
- 一份源码编译出多个版本（变体），由关键字组合决定
- N 个关键字，最多 2^N 变体

**爆炸代价：** 编译时间长、包体大、内存占用、加载慢

**multi_compile vs shader_feature：**

| | multi_compile | shader_feature |
|---|---|---|
| 编译 | 全量 | 只编译有材质用到的 |
| 适合 | 运行时动态切换（质量档、光照模式） | 材质级开关 |
| 坑 | 包体大 | 运行时切到没编译的变体，变粉/报错 |

**控制手段：**
1. shader_feature 替代不必要的 multi_compile
2. 变体剔除（Shader Variant Collection）
3. 合并关键字：用枚举代替多个 bool。反例：4 个 bool 混合模式 = 2^4=16 组合但只 4 种有效；正例：2 个关键字编码 4 种 = 4 变体
4. 运行时材质属性代替关键字
5. URP Shader Stripping

**项目：** MatCap 三种混合模式用 3 个独立关键字 = 理论 8 组合，实际只 3 种，可优化

## 25. SDF 阴影

**为什么脸部不用 Shadow Map：** 脸部曲面复杂（鼻/下巴/眼眶），普通阴影投出难看形状；二次元要求干净可控稳定

**SDF 是什么：**
- 预烘焙脸部阴影查找图
- 横轴 U：光照方向水平角（每个角度一列）
- 纵轴 V：脸部 UV 的某个轴（常取 UV.y 或按左右半边存）
- 存的是到阴影边界的距离，有正负（负=阴影内，正=阴影外）

**为什么叫有向距离场：** 存的是到边界的距离（不是 0/1），带正负，天然软过渡、抗锯齿

**采样逻辑：**
1. 光照角度对应 U
2. 脸部 UV.y 对应 V
3. 采样得 sdf 值
4. 拿当前像素 UV.x 和 sdf 比较：uv.x 小于 sdf 阴影内，否则亮部
5. smoothstep 做软边

**实战坑：** 左右对称只烘半边，镜像要翻 UV.x；光照角度正负映射不同

**vs Shadow Map：** Shadow Map 从光源投、逐像素比深度、物理通用；SDF 预烘焙、逐像素比 UV、只适合脸部，不物理但可控

## 26. 水面渲染

**结构（WaterPlaneMain.hlsl，169 行）：**

| 块 | 行 | 实现 |
|---|---|---|
| UV 动画 | 93-101 | 两层法线交叉采样，UV 随时间移动 |
| 法线采样 | 103-113 | 两张法线叠加 加 TBN 转世界空间 |
| 深度采样 | 115-119 | SampleSceneDepth 到 线性深度 到 depthDis |
| 水颜色 | 121-126 | lerp(浅水色, 深水色, depthDis) |
| 折射 | 128-136 | SampleSceneColor 加 屏幕 Y 缩放偏移 |
| 反射 | 138-149 | reflect() 加 CubeMap 加 菲涅尔 |
| 边缘泡沫 | 151-163 | 深度差阈值 加 smoothstep |

**关键点：**
- 深度水色：depthDis = 场景深度 - 水面自身深度，是差值不是插值。差越大水越深
- 波形交叉采样：同一张法线不同方向/缩放采两次，相加归一化，避免单层规律太明显
- 折射：屏幕坐标 加 偏移采 _CameraOpaqueTexture，项目里简化为屏幕 Y 缩放（非真折射）
- 反射：reflect 加 CubeMap（预烘焙非实时）加 菲涅尔（1-NdotV，掠射更强）
- 泡沫：深度差做阈值（水浅=近岸）加 smoothstep 软边
- Transparent 加 ZWrite On：防水面自身前后重叠画多次；代价是水下透明物体可能被挡
- 参数防 NaN：max(5 - _FresnelFactor 乘 0.5, 1e-3) 防 pow(0,0)；max(_EdgeFoamBlur, 1e-4) 防 smoothstep edge0 等于 edge1

## 附 1：贯穿所有主题的易错点

1. Rim 是加法叠加，不是 lerp 覆盖
2. Rim vs Outline：Rim=视角表面光，Outline=几何线；不能同 Pass（Cull 冲突）
3. 各向异性高光垂直于纹理，不是沿纹理
4. OIT = 顺序无关，不是无光
5. MSAA 是像素内子采样，不是周围像素平均
6. BC1 标准无 alpha，要 alpha 用 BC3/BC7
7. 金属 F0 带颜色，不是接近 1 的白
8. MR 只打包金属度加粗糙度，Albedo 单独
9. 法线变换用逆转置（非均匀缩放时）
10. Color Grading LUT 不等于 预积分皮肤 LUT
11. sRGB 解码非线性，会把数据贴图掰弯
12. shadowAttenuation 和 N dot L 独立，别混成阴影由 N dot L 决定
13. shader_feature 运行时切换会翻车（没编译的变体）
14. 深度水色是差值，不是插值

## 附 2：三个实战标志素材

**标志 1（具体坑）：**
- exp2(lerp(3,0,x)) 改成 lerp(3,0,x)，滑块拉到底全白（pow 指数趋 0 失控）
- 参数下限保护：max(..., 1e-3) 防 pow(0,0) 和 smoothstep edge 相等出 NaN
- SDF 脸部左右镜像要翻 UV.x，否则一边对一边错

**标志 2（取舍）：**
- NPR 的 LOD 比 PBR 保守（描边断裂、色阶硬边）
- 遮挡剔除宁可多画不可错剔
- 硬编码色阶 vs Ramp 贴图：羽化控制更灵活
- 卡通高光用 N dot H 不用 R dot V：更省、掠射更稳

**标志 3（知道没做到）：**
- 水面折射是屏幕 Y 缩放近似，不是真折射
- 自发光不能照亮别人，要额外加真实光源
- MatCap 三种混合模式用 3 个独立关键字，可合并优化变体
